# Sprint 1.12: WYSIWYG Authoring Experience

## 1. The Constitution (Editor Mandates)
1. **Persistence Immutability:** The database strictly stores raw Markdown. The Editor component must handle bidirectional translation: parse raw Markdown to TipTap AST on mount, and serialize TipTap AST to raw Markdown on save. 
2. **Headless UI Construction:** TipTap is headless. Do not rely on pre-packaged CSS. Build the Bubble Menu and Slash Menu using Tailwind CSS to match the existing application design system.
3. **Custom Extension Parity:** The WYSIWYG editor MUST support custom TipTap Node extensions for `[[Wiki-Links]]` and `::gm-secret`. The custom serializers must output the exact markdown syntax required by our Nuxt MDC viewer engine.
4. **Markdown Fallback:** The component must include an `isRawMode` toggle that destroys the TipTap instance and falls back to a native `<textarea>` bound directly to the Markdown string.

## 2. The Product Spec (User Flows)
* **Flow 1: Bidirectional Editing:** A GM loads a page containing `## History` and `[[The Harpers]]`. The editor parses this and visually displays an H2 header and a styled blue Wiki-Link bubble. The GM bolds a word. When saving, the system outputs standard Markdown: `## History` and `[[The Harpers]]` alongside the new `**bold**` syntax.
* **Flow 2: Slash Menu Context:** A GM presses `/` on an empty line. A floating Tailwind-styled dropdown appears at the cursor. They type "sec", press Enter on the "GM Secret" option, and a visually distinct striped block appears in the editor.
* **Flow 3: Asset Interception:** A GM drags and drops a `map.png` file into the editor. The editor intercepts the drop event, uploads the file via `AssetService`, and inserts a TipTap Image node, which serializes to `![map](cdn-url)`.
