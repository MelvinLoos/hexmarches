# Sprint 1.8: Asset Pipeline, Metadata & Lore Engine

## 1. The Constitution (Sprint Mandates)
1. **Asset Immutability:** All binary assets (images) are uploaded to the Supabase `wiki-assets` storage bucket. The PostgreSQL database stores strictly immutable public CDN URLs as metadata (`coverImageUrl`) or within raw markdown strings. 
2. **AST Transformation Boundary:** The conversion of `[[Wiki-Links]]` to Nuxt routing links must occur exclusively during server-side Markdown-to-AST compilation (using a custom Remark plugin). The raw markdown stored in the database must remain untouched.
3. **Asymmetric Security:** The `::gm-secret` MDC component must conditionally render based on the Nuxt session context. If the user lacks the `is_gm` claim, the component must completely omit its children from the Virtual DOM to prevent client-side data leaks.
4. **Domain Purity:** The `WikiNodeType` enum (`GENERAL`, `LOCATION`, `NPC`, `FACTION`, `ITEM`, `QUEST`) belongs strictly in the pure TypeScript Domain Layer.

## 2. The Product Spec (User Flows)
* **Flow 1: Metadata Extension:** The GM assigns a `WikiNodeType` and uploads a Cover Image via a dropzone above the markdown editor. The `coverImageUrl` is displayed as a hero header in the Wiki Viewer.
* **Flow 2: Inline Asset Upload:** Inside `md-editor-v3`, the GM clicks the image button, selects a local file, and the application orchestrates the upload to Supabase, injecting `![alt](cdn-url)` into the editor.
* **Flow 3: Rapid Lore Linking:** The GM types `[[The Harpers]]` in the editor. When a player views the page, the system dynamically parses the AST, looks up "The Harpers" in the wiki node dictionary, and renders a clickable `<NuxtLink>` pointing to its `ltree` path.
* **Flow 4: GM Secrets:** The GM writes `::gm-secret{title="Trap DC 15"}`. When viewing the wiki, players see nothing; the GM sees a visually distinct warning block containing the trap details.
